01

Choosing the right one

Before you drag a single node.

The filter

A good first automation passes all five.

01RepetitiveDo I do this the same way every time?
02Rule-basedCan I write the decision as if this, then that?
03High volumeDoes it happen often enough to matter?
04Low stakesIf it breaks quietly for a day, is anyone harmed?
05StableHas this process stayed the same for months?
Run two through the filter
Passes all five

New form response → log to a sheet → post to the team channel.

Same every time · clear rules · daily · nobody harmed if it stalls

Fails two

Deciding which client complaint gets a refund.

Not rule-based · two reasonable people decide differently
Not low stakes · real money, real relationship

The never list
  • Judgment calls.
  • Money or legal weight, unsupervised.
  • Processes that change every week.
  • One-off tasks. Just do the task.
  • Broken processes.

Automation multiplies whatever you point it at. Point it at something good.

02

The anatomy

Four parts. Every workflow, every time.

Plate 01 · The four parts
The happy path When it breaks
Part one of four

Trigger

What wakes it up.

  • ScheduleRuns on a clock, whether anything happened or not
  • EventSomething outside pokes it. A webhook, a new email
  • ManualYou press play. Mostly for testing
Common trap

Building on a schedule when an event trigger existed all along.

Part two of four

Action

What it actually does.

SendCreate UpdateFetch

Every action node is an API call wearing a friendly interface.

The thing to remember

Data flows forward. Each node only knows what the node before it handed over.

Part three of four

Logic

The decisions in between.

  • BranchDifferent paths for different data
  • LoopDo it once per item
  • MergeBring the paths back together
  • WaitPause, rate limit, or hold for a reply

Logic is where a workflow stops being a script and starts being a process.

Part four of four · the one everyone skips

What happens at 3am?

When the API is down and nobody is watching.

Nothing. And nothing is the problem.

The rule to give them

Every workflow that touches something real gets an error path, or it doesn't go live.

Every workflow is a trigger, some actions, some logic, and a plan for when it breaks.

Pick the boring, frequent, forgiving task. That's your first one.
